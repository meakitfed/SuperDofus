# Carte du code par domaine

Où vit chaque fonctionnalité (fichiers, données, mots-clés `client_shot`, tests). Les règles et les flux sont décrits dans `docs/ARCHITECTURE.md` ; les commandes dans `docs/COMMANDES.md`. Un nouveau domaine ajoute sa ligne ici (pas dans `CLAUDE.md`).

- Contenu (C.01) : `shared/content_source.gd` (`ContentSource`) est la seule porte vers `content/`, `data/`, `worlds/<id>/`, `mods/` (chemins logiques, `res://` ou cache `user://worlds/<id>/`) ; jamais de `res://content|data|worlds|mods` en dur (vérifié par `test_architecture`) ; le rendu lit via `client/content_provider.gd` (réglage `dofus_renderer/content_provider_script`). Voir « Contenu d'un monde » dans `docs/ARCHITECTURE.md`.
- `game/src/shared/` : logique pure commune à la sim et au client (géométrie des maps 14×20, A*, timing des mouvements, protocole).
- `game/src/sim/` : autoritaire, le serveur l'exécute tel quel. Pas de `Node`, déterministe (seed). `world_sim.gd` (`WorldSim`) n'est qu'un routeur (connexion, tick, drain, dispatch) : les règles de chaque domaine sont dans `world_items.gd`, `world_travel.gd`, `world_npcs.gd`, `world_quests.gd`, `world_jobs.gd`, `world_death.gd`, `world_fights.gd` (base `WorldHandler`). Un script ne dépasse pas 800 lignes (`tests/test_architecture.gd`) : découper par domaine avant. Combats complets dans `sim/fight/` : placement, initiative, effets et états (`FightEffects`), IA (`FightAI`), gains (`FightRewards`). Le personnage persistant (niveau, XP, inventaire) est dans `sim/character.gd`, sauvegardé via `Persistence` (interface injectée ; `FilePersistence` en standalone, une base côté serveur). `Clock` donne la date réelle, jamais `Time`/`OS` dans la sim. `DataFiles` est la seule lecture de fichiers autorisée (données statiques).

- `game/src/api/` : les hôtes. `LocalBackend` (un client), `LocalServer` (les mondes, partageable entre plusieurs backends), `FilePersistence`, `SystemClock`. `NetBackend` : le même `GameBackend` vers un serveur (WebSocket JSON). `game/src/server/` : le serveur réseau headless (`ServerHost`, `main.gd`) ; rien d'autre ne le référence. `game/src/client/` : nœuds Godot qui affichent les événements. `ClientSession` route les événements par domaine (`_on_*_event`) et garde l'action en attente dans un `PendingAction`.
