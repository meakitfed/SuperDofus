# Atelier de mondes (`atelier/`)

Site local pour créer et éditer un monde (`game/worlds/<id>/`) sans toucher au code Godot, avec une garantie de cohérence. Node ≥ 20, TypeScript. Roadmap : lots **W.01 à W.07** (`docs/ROADMAP.md`).

## État
- **W.01 fait : le harnais** (schémas, validateur, tests).
- **W.02 fait : serveur local + gestion de mondes.** `atelier.bat` (ou `cd atelier && npm run build && npm start`) ouvre http://127.0.0.1:5174 : liste des mondes, création, détail avec panneau Cohérence, renommer, annuler/refaire, relire le dossier, supprimer.
- **W.03 fait : bibliothèque d'images.** Onglet « Images » d'un monde : glisser-déposer de PNG/JPEG/WebP ou d'un ZIP, par catégorie (objets, sorts, monstres, tuiles). Icônes ramenées à 96×96 transparent, tuiles gardées à leur taille. Chaque image est ré-encodée en PNG propre (aucune métadonnée), dédoublonnée par empreinte, numérotée dans la tranche `asset` du monde. Une image utilisée ne peut pas être supprimée ; une image inutilisée donne l'avertissement `W_ASSET_UNUSED`. Les imports ne passent pas par annuler/refaire (fichiers écrits aussitôt).
- **W.04 fait : éditeurs de données.** Fait : textes, objets, panoplies, sorts (onglets « Textes », « Objets », « Sorts »). Sorts : un grade lançable + sa famille ; effets simples (dommages, soin, bouclier, PA, PM), le critique est calculé (+30 %) ; un sort à effets riches reste éditable sur ses réglages, effets verrouillés. Chaque action (`core/editors.ts`, API `/api/worlds/:id/data/<texts|items|sets>`) est une étape d'annulation, passe par un texte i18n (jamais de nom en dur), prend son id dans la tranche du monde, et refuse une suppression qui laisserait une référence cassée (`core/usage.ts` : « utilisé par »). La pastille de cohérence reste visible en édition. Monstres : 1 à 5 grades (stats, résistances, sorts, butin, kamas, agression), squelette copié depuis un autre monde géré (les aperçus sont les planches brutes `0.png`), zones de monstres (clés comptées depuis le haut de la plage `monster`) ; règle `W_MONSTER_NO_ZONE` (56 règles) ; les boss sont en lecture seule. Une zone n'est rattachée à une map que dans l'éditeur de maps (W.05). Classes : nom, rôle, description, squelette, grimoire ordonné (un sort ne sert qu'une classe), classe par défaut ; nouveau type d'id `breed` (plafond de 600 emplacements pour rester sous 2^31). Le contrat Godot couvre un monde rempli avec les éditeurs. Limite : pas encore de symbole ni de portrait de classe (écrans de création du jeu).
- **W.05a fait : éditeur de maps** (onglet « Maps »). Grille 14×40 cliquable (murs, vue bloquée, placement rouge/bleu, porte, renaissance, départ du monde ; glisser pour peindre), nom, coordonnées, extérieur, zone de monstres, voisines (réciproques automatiquement), portes. Une map s'enregistre d'un bloc (une étape d'annulation). L'éditeur refuse ce que le validateur rejetterait aussitôt : porte ou arrivée sur un mur, placement sur un mur, départ bloqué, élément interactif libéré. Créer une map crée son visuel vide ; supprimer une map efface ses fichiers (copie `.bak`, annulation possible) et exige qu'aucun lien, PNJ ou quête n'y mène. Murs = `blocked` et `fight_blocked` écrits ensemble. Le dessin des calques graphiques reste W.07.
- **W.05b fait : PNJ, dialogues, boutiques, banque** (onglet « PNJ »). Placement sur une grille cliquable (la cellule devient un obstacle, comme dans les mondes générés ; la map refuse de la libérer), nom, orientation, squelette, boutique, banquier. Dialogue : nœuds, réponses, destination, critères (`Qf=` quête, `PO=` objet, vérifiés), actions (boutique, banque, téléportation, don d'objet) ; une réponse ne peut proposer ni boutique ni banque que le PNJ n'a pas ; un nœud jamais atteint est signalé. Nouvelle règle `E_NPC_BONE` (57 règles). Retirer un PNJ efface son dialogue, sa boutique et son entrée de banque, et est refusé s'il sert une quête.
- **W.05c fait : quêtes** (onglet « Quêtes »). PNJ donneur (la map est lue sur son placement), niveau, répétition, étapes réordonnables avec titre, description et niveau ; objectifs : parler, retourner voir, apporter des objets, découvrir une map, vaincre un ou plusieurs monstres ; récompense par étape (ratios d'XP et de kamas du jeu, objets). Les textes d'objectifs du journal sont construits depuis les noms des cibles, rien n'est saisi deux fois. Une quête qui utilise des objectifs ou récompenses hors formulaire (types 0/2/5/6/8/16/17, émotes, titres…) reste en lecture seule, ses données ne sont jamais réécrites. Une quête citée par un critère de dialogue (`Qf=`) ne peut pas être supprimée ; PNJ, monstre et objet qu'elle utilise sont protégés. Le jeu ajoute lui-même la réponse qui propose la quête au PNJ donneur. W.05 terminé.
- **W.06a fait : rapport « monde jouable »** (panneau de la vue d'ensemble, `core/playable.ts`, `GET /api/worlds/:id/report`). Huit questions, chacune avec son test par casse et une garde de couverture : chaque classe a un sort de niveau 1, chaque monstre est rencontrable (zone sur une map atteignable avec apparitions), chaque zone sert, boutiques et banques s'ouvrent par le dialogue, chaque quête peut être commencée puis terminée (PNJ, maps, monstres, objets atteignables), les niveaux d'étapes croissent, chaque objet s'obtient (butin, boutique, récompense, don, récolte). Atteignabilité = portes, voisines, téléportations de PNJ depuis la map de départ. Sur La Vertèbre : 3 objets sur 124 (9100030, 9100043, 9100044) n'ont aucune source.
- **W.06b fait : « Vérifier avec le jeu »** (bouton sous « Monde jouable ? », `core/gamecheck.ts`, `POST /api/worlds/:id/gamecheck`). Lance Godot en headless (`sim_cli.gd --world=<id>`, comme le test de contrat) sur le monde enregistré et juge la sortie : accueil au nom du monde, entrée sur une map, aucune erreur de script, délai de 120 s. Réponses `ok`, `failed` (avec les lignes d'erreur) ou `unavailable` (Godot introuvable, `GODOT_EXE` pour l'indiquer ; dossier de mondes hors projet Godot). Jamais de fausse réussite.
- **Assistants guidés** (onglet « Assistants », `core/workflows.ts`, `GET /api/worlds/:id/workflows`) : six parcours (classe jouable, monstre + butin + zone, quête, donjon, relier deux maps, PNJ marchand). Chaque étape est cochée d'après les données du monde (et les vérifications du rapport jouable), sans état mémorisé : un assistant ne peut donc pas laisser une référence cassée sans que son étape le montre. Le bouton mène à l'éditeur de la prochaine étape. Tests : monde jouable = assistants terminés, et chaque casse défait l'étape visée.
- **W.07 fait : éditeur de décor** (onglet « Décor », `core/editors_visual.ts`, `GET/PUT /api/worlds/:id/data/visuals/<map>`). Les trois couches du visuel d'une map (`Content/Maps/<visual>.json`) : sol, objets posés sur une cellule (triés par cellule puis ordre), premier plan, plus la couleur de fond. Une image est une tuile de la bibliothèque (catégorie « Tuiles de map ») placée par le centre de son sprite en pixels de map (cellule 0 = 0,0 ; convention du jeu, 86 x 21,5). Clic sur l'aperçu = pose ; un objet se cale sur la cellule la plus proche, pied de l'image sur la cellule ; flèches, cellule, ordre, retrait. Refus : image absente de la bibliothèque, cellule ou position hors map, plus de 400 éléments par couche. Les champs inconnus d'un élément (teinte) sont conservés à son rang. Le décor ne bloque rien (murs = onglet Maps). Un décor partagé par deux maps est signalé. Annulable (une étape d'annulation par enregistrement).
- **W.08 fait : dupliquer un monde** (bouton « Dupliquer… », `core/clone.ts`, `POST /api/worlds/:id/clone`). Copie le dossier d'un monde créé par l'atelier dans un nouveau, et décale tous ses numéros vers un nouvel emplacement : un nombre, une clé d'objet ou une suite de 10 chiffres dans un texte (critères `Qf=`, arguments) qui tombe dans une plage de l'original est un id et rien d'autre (plages disjointes, Dofus < 4e8, couleurs > 2^31) ; les noms de fichiers-id (`Maps/<id>.json`, images, squelettes) suivent. La copie est relue et comparée à l'original (même nombre de problèmes) avant d'être gardée, sinon elle est supprimée. Refusé pour La Vertèbre (numéros propres, petits : pas de décalage sûr).
- **W.09 fait : schéma des dialogues** (`core/dialog_graph.ts`, `DialogGraph.tsx`, dans l'éditeur de dialogue, « Voir le schéma de la conversation »). Boîtes en colonnes selon la distance au nœud de départ, une flèche par réponse qui mène à un nœud (pointillée si elle revient en arrière), nœuds jamais atteints en dernière colonne, en pointillés. Lecture seule : l'édition reste dans les cartes de nœuds.
- **W.10 fait : exporter / importer un monde** (`core/exchange.ts`, « Exporter (.zip) » dans l'en-tête d'un monde créé par l'atelier, « Importer un monde (.zip) » sur la liste, `GET /api/worlds/:id/export`, `POST /api/import`). L'archive contient le dossier (sans `.bak`) et un manifeste `atelier_world.json` avec les plages d'ids : à l'import, le monde est décalé vers un emplacement libre comme une copie, relu et comparé à l'original avant d'être gardé. Refus : archive illisible ou étrangère (pas de manifeste), chemin hors du dossier (`../`), plage absente, `world.json` illisible, identifiant pris ; limites 20 000 fichiers et 400 Mo décompressés. La Vertèbre ne s'exporte pas.
- **W.11 fait : copier une map** (liste déroulante « Point de départ » de « Nouvelle map », `createMap(..., copyOf)`). La nouvelle map reprend la grille (murs, vue, placement, renaissance) et une copie du décor ; elle ne reprend ni voisines, ni portes, ni PNJ, ni groupes de monstres fixes. Idéal pour les salles d'un donjon.
- **W.12 fait : bibliothèque Dofus** (bouton « Bibliothèque Dofus… » de l'onglet Images, `core/library.ts`, `GET /api/library/<catégorie>[/<id>.png]`, `POST /api/worlds/:id/library/<catégorie>`). Parcourt les images du jeu déjà présentes sur l'ordinateur (`game/content/Content` : icônes d'objets, de sorts, de monstres, tuiles de map), recherche par numéro, pages de 60, vignettes PNG réduites. Les images choisies (100 au plus) sont copiées dans le monde comme de simples images importées (mêmes règles : 96 x 96 pour les icônes, doublons repérés) : le monde garde sa copie et marche sans le contenu Dofus, qui n'est jamais publié. Bibliothèque absente = message clair.
- **W.12b fait : squelettes du jeu Dofus** (bouton « Squelettes du jeu Dofus… » du sélecteur de squelette, classes, monstres, PNJ). Liste les dossiers numériques de `Characters/Bones` (7 800 dans le jeu), aperçu = planche de dessins `0.webp`, et copie le dossier entier dans le monde (un monde reste complet par lui-même). Les paquets de classes de joueur (`1-12-combat`) ne sont pas proposés. Corrigé au passage : une route d'aperçu absent écrivait ses en-têtes avant de lever l'erreur (plantage « Cannot write headers »), maintenant 404 JSON propre, avec test de régression.
- **W.13 fait : armes et objets du jeu comme modèles** (`core/editors.ts`, `core/library_items.ts`, `GET /api/library/items-templates?q=`). L'éditeur d'objets gère maintenant les **statistiques d'arme** (PA, portée min/max, coup critique et bonus, tir en ligne, ligne de vue, coups par tour ; bornes vérifiées, refusées sur ce qui n'est pas une arme) et la règle `W_WEAPON_NO_STATS` signale une arme sans elles. « Partir d'un objet du jeu Dofus » cherche dans `game/data/items.json` (nom sans accent ni majuscule, ou numéro ; 653 armes et les types que le formulaire connaît), remplit le formulaire (nom, type, niveau, prix, effets, arme) et copie l'icône dans le monde. Les effets d'arme (96-100, 108) rejoignent la liste des effets du formulaire.
- **W.14 fait : monstres du jeu comme modèles** (`core/dofus_text.ts`, `core/library_monsters.ts`, `GET /api/library/monsters-templates?q=`). « Partir d'un monstre du jeu Dofus » dans le formulaire de monstre : recherche par nom (lu dans `I18n/fr.bin` du client, sans accent ni majuscule) ou par numéro parmi les 1 182 monstres de `game/worlds/dofus/monsters.json`. Reprend jusqu'à 5 grades (niveau, vie, PA, PM, XP, caractéristiques, résistances, kamas, agression), la taille, copie le squelette (dossier du jeu) et le portrait dans le monde. Les sorts et le butin ne viennent pas (ils pointeraient vers des choses absentes du monde) : le formulaire le dit et on les choisit parmi ceux du monde.
- **W.15 fait : réutiliser une vraie map du jeu** (bouton « Réutiliser une map du jeu… » de l'onglet Maps, `core/library_maps.ts`, `GET /api/library/maps-templates?q=`, `POST /api/worlds/:id/dofus-map`). Recherche par coordonnées du monde (`-3,5`, via `coords.json`) ou numéro de map ; chaque résultat montre le nom du lieu (textes du client), les coordonnées, extérieur/intérieur, le nombre d'éléments de décor et un aperçu des murs. La copie reprend la grille (murs, vue, placement de combat, filtré sur les cellules valides et libres), une cellule de renaissance libre est choisie au milieu, et le décor entier est copié avec ses images (WebP du jeu copiées dans `Content/Maps/Gfx` ; un élément dont l'image manque est laissé de côté et compté). Ni voisines, ni PNJ, ni zone de monstres, ni groupes fixes : la map arrive non reliée, l'assistant « relier » prend le relais. Le décor garde l'échelle, le retournement et la teinte de chaque élément (`m`, `tint`), l'aperçu les rend, les maps du jeu pouvant avoir plus de 2 000 éléments (limite portée à 4 000 par couche). `E_MAP_GFX` accepte `.png` ou `.webp`. Les images WebP sont servies en PNG à l'éditeur. Vérifié avec une vraie map (100139008) : 0 erreur de cohérence et le monde démarre dans la simulation Godot avec cette map comme départ.
- **Historique borné** : 200 étapes d'annulation au plus, et un fichier inchangé entre deux étapes partage la même chaîne en mémoire (un monde avec plusieurs maps du jeu de 180 Ko ne coûte plus que ce qui change).
- **Piste notée, pas faite** : un essai de combat dans « Vérifier avec le jeu » (`sim_cli --bot=fight --cmd=<ms>:tp:<map>:<cellule> --cmd=<ms>:fight_attack`). Le `tp` ne prend un numéro de map qu'au-dessus de 10 000 (en dessous, ce sont des coordonnées) : utilisable pour les mondes créés par l'atelier, pas pour La Vertèbre.
- Suite : assistants pas à pas et « vérifier avec le jeu » (W.06b), éditeur de calques de map (W.07), workflows (W.06), éditeur de calques de map (W.07). Le clonage de monde (qui exige de remapper tous les ids) n'est pas fait.

## Mondes gérés
- Seuls les mondes du registre sont modifiables : `vertebre` (plages historiques) et ceux créés par l'atelier (`atelier/world_ranges.json`, local, ignoré par git). `dofus`, `incarnam`, `test` sont listés en lecture seule.
- L'atelier ne supprime que les mondes qu'il a créés.
- Chaque monde créé a un emplacement (`core/ranges.ts`) : une tranche de 100 000 ids par type (textes, objets, sorts, monstres, PNJ, quêtes, maps...), tous au-dessus de 1 000 000 000. Les règles `E_ID_RANGE` et `E_ID_COLLISION` les font respecter. Un monde neuf n'a pas de classe propre (`breeds: []`) : le moteur lui offre alors les classes que personne ne réclame.
- Un monde neuf a une map vide (`templates/map_visual_empty.json`, sans image : rien à afficher tant que l'éditeur de calques, W.07, n'existe pas).

## Sécurité du serveur
Écoute 127.0.0.1 seulement, refuse un `Host` étranger (DNS rebinding), exige `x-atelier: 1` et du JSON pour toute écriture (aucun CORS), ne sert jamais de fichier hors de `web/dist`.

## Disposition
- `atelier/core/` : TypeScript pur.
  - `schemas.ts` : un schéma par fichier d'un monde (strict sur ce que le moteur lit, `passthrough` sur le reste).
  - `io.ts` : `loadWorld`, `saveWorld` (atomique : `.tmp` puis renommage, ancienne version en `.bak`), `serializeWorld`. **Le modèle est le JSON brut** : l'ordre des clés et les champs inconnus survivent à un aller-retour.
  - `validate.ts` + `rules_content.ts` / `rules_maps.ts` / `rules_story.ts` : les règles. `RULES` est la liste unique ; un `Problem` porte un code stable, un message français et une référence (`ref`) pour que l'interface mène à l'élément fautif.
  - `grid.ts` : grille 14 × 40 = 560 cellules, voisinage en diagonale (le plus strict).
  - `cli.ts` : `cd atelier && npm run validate -- ../game/worlds/<id>` (code de sortie 1 s'il y a des erreurs ; les avertissements `W_*` n'échouent pas).
- `atelier/tests/` : voir ci-dessous.

## Ajouter une règle
1. L'écrire dans le fichier de règles du domaine : `{ code: "E_…", severity, doc, run }`. Préfixe `E_` (erreur) ou `W_` (avertissement), imposé par le test.
2. Ajouter sa mutation dans `tests/rules.test.ts` (`MUTATIONS`) : partir du mini-monde, casser **une** chose. La mutation ne doit déclencher que cette règle (sauf `also` justifié). La garde de couverture échoue sinon.
3. Si la règle a un équivalent dans `worlds_src/vertebre/gen/validate.py`, ajouter une casse dans `tests/vertebre.test.ts` (parité des verdicts).

## Pièges
- `npm install` plante (« edgesOut ») sans `legacy-peer-deps` : déjà dans `atelier/.npmrc`.
- Les messages de `validate.py` sont en anglais, ceux de l'atelier en français : la parité compare les **nombres** de problèmes, pas le texte.
- Les ids doivent être disjoints entre mondes et de `data/` global : `opts.ranges` / `opts.reserved` de `validate()` (alimentés par W.02).
